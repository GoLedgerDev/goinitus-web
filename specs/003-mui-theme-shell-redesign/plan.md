# Implementation Plan: UI Design Overhaul — Modern MUI Theme & Shell Redesign

**Branch**: `003-mui-theme-shell-redesign` | **Date**: 2026-03-25 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/003-mui-theme-shell-redesign/spec.md`

## Summary

Replace the default MUI tutorial appearance with a professional blockchain operations UI. One new module (`src/theme.ts`) provides a `buildTheme(primaryHex)` factory that wires the connected chaincode's brand colour into every MUI primary-colour element via `useMemo` in `App.tsx`. Layout shifts from an overlay-only Drawer to a permanent sidebar on desktop (using responsive `useMediaQuery` branching). The Drawer interior is redesigned with icons, an active-route highlight, and a bottom-pinned settings entry. The asset list page gets a Paper header card and a per-row overflow menu replacing three always-visible icon buttons. Previous-page navigation is added via a bookmark stack. The asset detail page gets a structured paper header, a two-column property grid, and KEY chips on key fields.

**No new npm packages. No API, store, routing, or data logic changes.**

## Phase 0 Research Summary

All research questions were resolved via direct analysis of MUI v6 source and documentation. Full findings in [research.md](research.md). Key decisions:

| ID | Topic | Decision |
|---|---|---|
| R-001 | `alpha()` import | `import { alpha } from '@mui/material/styles'` — stable in MUI v6 |
| R-002 | AppBar sticky vs fixed | Switch to `position="sticky"` inside column-flex — eliminates Toolbar spacer hack |
| R-003 | Drawer variant props | Permanent ignores `open`/`onClose`; temporary requires them; share same `sx` sizing |
| R-004 | DataGrid alternating rows | `getRowClassName` + `sx` rules — CSS `:nth-of-type` unreliable with virtual rendering |
| R-005 | DataGrid no border | `border: 0` on `root` styleOverride + `overflow: 'hidden'` for border-radius clipping |
| R-006 | Active nav highlight | `useLocation().pathname.startsWith(...)` + conditional `borderLeft` + `bgcolor` |
| R-007 | Bottom-pin settings | `flexGrow: 1` on nav scroll area + no-grow on settings Block — standard flex footer pattern |
| R-008 | Previous-page pagination | `pageStack: string[]` of input bookmarks — stack grows on Next, shrinks on Previous |
| R-009 | Row-level overflow menu state | Single `{ anchorEl; rowKey } | null` state; Menu rendered outside DataGrid to avoid z-index issues |

## Implementation Order

The 13 file changes must be implemented in dependency order:

```
1. index.html          → font availability (no code deps)
2. src/theme.ts        → new module (no deps on other modified files)
3. App.tsx             → depends on theme.ts + globalStore.orgColor (already exists)
4. Header/index.tsx    → add props (consumed by AppShell in step 5)
5. AppShell.tsx        → orchestrates Header + AppDrawer; depends on steps 4, 6
6. Drawer/index.tsx    → depends on new props designed in step 5
7. AssetNavItem.tsx    → depends on Drawer index refactor (step 6)
8. TxNavItem.tsx       → same as step 7
9. AssetDetail.tsx     → standalone; no deps on steps 1-8
10. AssetHistory.tsx   → depends on AssetDetail (step 9) — reuses AssetDetail styling
11. AssetItemPage.tsx  → depends on AssetDetail style (step 9); header card is local
12. AssetListPage.tsx  → add pageStack state; pass new props to AssetTable (step 13)
13. AssetTable.tsx     → depends on new props from AssetListPage (step 12)
```

Steps 9–10 can be parallelised. Steps 7–8 can be parallelised. Steps 1–3 can be done in any order among themselves.
